Menus, OTP inputs, upload staging, command palettes. The components every product
needs, built once with the details usually skipped: interruptible animations,
keyboard paths, reduced-motion, and the awkward states nobody demos.

Every component is **React 19 + Tailwind v4 + [motion](https://motion.dev)**, shipped through a
**shadcn registry**. There is no runtime package: the CLI copies the source into your
repo and you own it from there.

## Quickstart

```bash
npx moumenlab add otp-segmented-input
```

```tsx
import OtpInput from "@/components/lab/otp-segmented-input";

export default function Verify() {
  return <OtpInput length={6} verify={(code) => code === "246810"} />;
}
```

That is the whole loop: install, import, use. The file lands in
`components/lab/`, and it is yours to edit.

## What you get

<AccordionGroup>
  <Accordion title="Source you own, not a dependency" icon="code">
    The registry copies `.tsx` files into your project. No `moumenlab` import at
    runtime, no version to keep in step, no wrapper to fight when a design
    changes. Delete half of a component if you only need the other half.
  </Accordion>
  <Accordion title="Fully Tailwind, no stylesheet to import" icon="palette">
    No CSS files and no custom classes anywhere. Shared design tokens live in a
    single registry item, [`lab-theme`](/theme), which merges into your `@theme`
    block on install.
  </Accordion>
  <Accordion title="Motion-first, and honest about it" icon="wand-magic-sparkles">
    Animations use `motion/react` so they stay interruptible and layout-aware.
    Every component root wraps in `<MotionConfig reducedMotion="user">`, so the
    system preference is respected without an extra prop.
  </Accordion>
  <Accordion title="An inspect mode built in" icon="eye">
    Every component takes `inspect` and most take `onStateChange`. Turn them on
    to outline the geometry and stream the internal state, which is how the
    blueprints on the site are drawn.
  </Accordion>
</AccordionGroup>
